## Why these five

Together they create one small control plane around mechanisms gwonmac already
owns:

```text
inspect -> discover -> prove -> transform -> install -> observe -> retain
```

- Plan 001 lowers lookup cost without changing authority.
- Plan 002 makes a refusal diagnosable at its real boundary.
- Plan 003 prevents the repeated “correct bytes, wrong meaning” failure class.
- Plan 004 makes the strongest reproducibility claim honest and executable.
- Plan 005 makes current operational fact support queryable, then removes the
  one architectural authority contradiction found in production.

## Findings considered but not promoted to current plans

- **Generic agent/MCP platform — rejected.** It would duplicate the existing
  certification CLI, scenario registry, diagnostics, and process lifecycle.
- **Generic memory/call/packet API — rejected.** It weakens the bounded semantic
  contracts and safety rules in `docs/wasm-host.md` and
  `docs/enhancement-development.md`.
- **A separate knowledge database — rejected.** Current behavior belongs in
  `docs/` and executable contracts; costly negative knowledge fits the existing
  investigation records once provenance and witness metadata are required.
- **Generate the complete companion ABI now — deferred.** The ABI has several
  manually synchronized forms, but current compile-time and runtime checks fail
  closed. Reconsider a generator only after Plans 001-003 provide inspection
  and phase evidence, and only if a measured drift incident remains.
- **Automatically reacquire old ArenaNet builds — rejected.** Availability,
  authorization, and retention are human constraints. Plan 004 declares exact
  needs without inventing a remote distribution system.
- **Bit-identical signed/notarized application reproduction — deferred.** The
  actionable claim is deterministic repository-owned transforms over exact
  official inputs. Packaging identity needs a separate explicit product need.
- **Move Cartography into the Enhancement bitmask — rejected.** It has a distinct
  predecessor and transform contract. It should share verifier authority, not
  pretend to be the same stage.
- **Revalidate every Toolbox++ mask in Plan 005 — deferred.** The authority
  correction and the semantic dataset audit are separate risks. Toolbox++
  provenance remains useful, but future product claims should name a local
  visual/coverage witness and applicable game-data version.
