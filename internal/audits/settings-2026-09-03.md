# Launcher settings audit — 3 September 2026

Scope: launcher Settings, account colors, and settings delivery to open game
windows. This is normal development from `main`. The supplied screenshots are
evidence of the reported defects. They are not a separate instruction source.

## Verdict

The original implementation failed the settings contract. A generic text-input
rule collapsed native color swatches. Moving Settings removed the game host's
settings subscription and left supported appearance preferences without a UI.
The repairs keep the existing launcher visual system and durable settings file.

| Dimension | Before | After | Evidence and limit |
| --- | --- | --- | --- |
| Accessibility | 2/4 | 3/4 | Named controls, local validation errors, visible focus, picker plus hex entry, slider plus number entry. No screen-reader certification. |
| Performance | 3/4 | 3/4 | Native controls; no new dependency or polling. Slider drags preview locally and save on release. No performance benchmark. |
| Responsive design | 1/4 | 3/4 | Editor rows wrap; controls have bounded widths. Electron checks cover ordinary and minimum windows, including 200% zoom. |
| Theming | 2/4 | 3/4 | Existing launcher palette preserved. Restored in-game styles, fonts, opacity, and custom colors. Arbitrary player palettes are not an accessibility guarantee. |
| Implementation integrity | 1/4 | 4/4 | One durable publication path feeds launcher and game renderers; restored controls use existing domain values and validation. |
| Total | **9/20 — Poor** | **16/20 — Good** | Scores describe this scoped audit, not whole-app WCAG conformance. |

Nine material findings: four P1, five P2. No P0 finding. All nine are
addressed by this change. The Impeccable mechanical detector returned no
findings; the functional and layout defects required direct inspection.

## Findings and repairs

| Priority | Finding and impact | Location | Repair |
| --- | --- | --- | --- |
| P1 | Color swatches appeared as lines; users could not inspect or type the selected color. | `apps/launcher/src/style.css`, map and cooldown editors | Restrict text-field styling to text-like inputs. Share a 44-pixel picker and validated hex field across map, timer, panel, and account colors. |
| P1 | Saved launcher changes did not reach the active game presentation. The launcher also missed changes made inside a game. | `src/renderer/harness.ts`, `src/main/main.ts` | Subscribe before the initial read, preserve newer events, unsubscribe on teardown, and publish to the launcher from the existing settings owner. Remove duplicate local application after a map write. |
| P1 | Panel style, custom colors, font, opacity, and controller symbols had durable values but no launcher controls. | Launcher contract, snapshot, Game settings | Restore the controls and existing theme sharing. Validate the narrow launcher boundary. Retain the custom palette when choosing a built-in style. |
| P1 | At 200% zoom the sticky navigation remained vertical and covered the editor. Geometry-only tests missed the obstruction. | Responsive Settings navigation | Set the compact navigation to a horizontal row, reserve scroll space for it, and verify each input with a real hit test. |
| P2 | Sliders hid exact widths and offered no numeric entry. | Map editor | Pair sliders with bounded integer fields and units; show current values during dragging. Reject empty, fractional, and out-of-range values. |
| P2 | Shortcut content touched the preceding separator. | `ShortcutSetting.vue`, feature detail rows | Give shortcut sections 20 pixels of vertical padding and consistent horizontal alignment. |
| P2 | Line editors packed several controls into a brittle fixed grid. | `MapsSettings.vue`, launcher stylesheet | Group each line's color, width, and pattern into labeled rows. Wrap controls at narrow widths; separate unseen-cell color from marker selection. |
| P2 | Some descriptions implied the wrong effect or omitted restart timing. | Game and Advanced settings; user guide | Explain immediate render-quality changes, application-restart memory changes, next-open/reload controller symbols, and diagnostics overlay visibility. |
| P2 | One field served both export and import; clearing it restored the export text. Invalid names and preset limits could fail silently. | Map style actions | Separate readonly sharing text from import input. Keep failed imports available for retry and explain invalid names and the custom-style limit. |

## Evidence

- Launcher unit tests cover valid and invalid hex, slider preview and commit,
  numeric bounds, custom theme persistence, import rejection, and save failure.
- The launcher boundary rejects unknown appearance choices, malformed themes,
  unknown theme fields, and invalid opacity values.
- Offline Electron tests exercise real launcher IPC and two open game windows.
  They observe the game host applying settings, inspect resulting appearance
  attributes, and verify game-to-launcher map changes through the rendered UI.
- Electron checks inspect every map editor input for a name, usable dimensions,
  horizontal containment, and unobstructed hit targets at ordinary size, minimum
  width, and 200% zoom.
- The repository gate is `pnpm check`; the build is `pnpm build`.

The existing typed feature boundaries, native keyboard controls, error handling,
atomic preference writes, reduced-motion handling, and separate restart-only
resources remain useful foundations. No new persisted state, migration, polling
loop, generic bridge, or dependency was needed.

## Remaining verification boundary

Offline fixtures prove delivery and renderer application. They do not prove
native map pixels, input feel, or gameplay. Matthias should change a grid style
and layer visibility while playing a supported map in a Developer Build.
Optional Tools and Maps must be active in that session. A release that includes
this renderer lifecycle change merits Beta consideration under repository policy.

Impeccable also reported that `PRODUCT.md` predates its current metadata schema.
That is unrelated project-context maintenance; `impeccable init` owns that work.


## Follow-up from player testing

Player testing found that selecting or extending an existing custom style failed.
The first audit's single-preset fixture missed this. A new Electron test first
reproduced the error after creating a preset and selecting another built-in.

The launcher now keeps native snapshots in a shallow Vue reference. The existing
whole-snapshot replacement model does not need deep proxies, and reused preset
objects can cross Electron's context bridge. The regression test covers two
custom presets, style selection, editing, and editing again after launcher reload.

Terrain border thickness is now available in the main map controls, including
built-in styles. The first edit saves a custom copy instead of introducing a
second global border-width override. The Compass grid has one separate opt-in,
defaulting to off. Turning it off leaves the Mission Map and World Map grid on.

Follow-up verification passed: `pnpm check` (1,561 unit, 181 policy, 146 Tools,
and 71 launcher tests), production build, and three focused Electron tests for
existing preset edits/reload, controls at 200% zoom, and settings delivery to two
open offline game windows. Native gameplay rendering remains player verification.
